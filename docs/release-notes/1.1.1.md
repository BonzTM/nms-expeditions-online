Play any expired No Man's Sky expedition online with full multiplayer — see other players, visit the Anomaly, and play with friends.

Drop in your expedition JSON, run the tool, and launch the game. The local proxy intercepts NMS season data and patches the auth response so the game believes your chosen expedition is active. All other traffic (multiplayer, discovery services, bases) passes through untouched.

## Features

- Full multiplayer support — Steam P2P networking is unaffected; you'll see other players and can group up normally
- Automatic expedition loading — The proxy serves expedition data directly to the game with the correct hash and content type. No manual file placement into game directories needed.
- Ephemeral TLS certificates — CA and per-host certificates are generated in memory at runtime. Nothing left on disk.
- Validated upstream connections — All traffic forwarded to real NMS servers uses proper SSL certificate validation
- HTTP keep-alive — Handles multiple requests per connection
- Cross-platform — Windows (.exe with automatic UAC elevation) and Linux (./run.sh handles everything)
- Simple menu interface — Install hosts entries, start the proxy, uninstall when done

## Getting Started

1. Download your expedition from https://cwmonkey.github.io/nms-expeditions/
2. Place SEASON_DATA_CACHE.JSON next to the executable (Windows) or in the project directory (Linux)
3. Run the tool, install, start the proxy, launch NMS

See the README.md for detailed instructions.

## 1.1.1 — Security Hardening & Project Infrastructure

This release addresses five security findings and adds the project infrastructure needed for community contributions.

### Security

- **Proxy no longer exposed to the network** — The listener now binds to `127.0.0.1` instead of `0.0.0.0`. Previously, any machine on the local network could connect to the proxy on port 443. Since all traffic is redirected via the hosts file to localhost, there was never a reason to listen on all interfaces.
- **Resource exhaustion protection** — Added limits to prevent denial-of-service against the privileged proxy process: max 64 KB headers, max 10 MB body, and max 32 concurrent connections. Connections exceeding these limits are rejected.
- **Windows command hijacking prevented** — `certutil` and `ipconfig` are now invoked using absolute paths to `%SYSTEMROOT%\System32`, preventing a malicious executable placed alongside the `.exe` from being run as administrator.
- **Atomic hosts file writes** — The hosts file is now updated via temp file + `os.replace()`, preventing corruption if the write is interrupted or another process edits the file concurrently.
- **Linux bootstrap hardened** — `run.sh` no longer runs `pip` as root or passes `-E` to `sudo`. Dependencies are installed as the regular user before elevating, preventing environment variables like `PIP_INDEX_URL` from redirecting package installs to attacker-controlled sources.

### What's New

- **Test suite** — 30 tests covering DNS resolution, hosts file management, HTTP parsing, chunked decoding, response rebuilding, and expedition data patching. Run with `pytest`.
- **CI pipeline** — GitHub Actions workflow runs `pytest` and `ruff` on every push and PR across Python 3.10, 3.11, and 3.12.
- **Community files** — Added `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, GitHub issue templates (bug report, feature request), and a pull request template.
- **README badges** — License, CI status, and latest release badges.
- **Release notes** — In-repo release notes for all versions in `docs/release-notes/`.

### Changed

- Pinned `cryptography` dependency to `>=42,<45` (was unpinned)
- Added type hints to all functions missing return annotations
- Fixed lint issues identified by `ruff` (semicolons, line length, ambiguous variable names, unused imports, import sorting)
- Linux release tarball now includes `pyproject.toml` and `run.sh`
- Added `authors`, `urls`, and `classifiers` to `pyproject.toml`
- Added `ruff` and `pytest` as optional `[dev]` dependencies
- Expanded `.gitignore` with OS files (`.DS_Store`, `Thumbs.db`), IDE directories (`.vscode/`, `.idea/`), and virtual environments (`venv/`, `.venv/`)
