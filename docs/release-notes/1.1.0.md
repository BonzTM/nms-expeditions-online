Play any expired No Man's Sky expedition online with full multiplayer — see other players, visit the Anomaly, and play with friends.

Drop in your expedition JSON, run the tool, and launch the game. The local proxy intercepts NMS season data and patches the auth response so the game believes your chosen expedition is active. All other traffic (multiplayer, discovery services, bases) passes through untouched.

## Features

- Full multiplayer support — Steam P2P networking is unaffected; you'll see other players and can group up normally
- Automatic expedition loading — The proxy serves expedition data directly to the game with the correct hash and content type. No manual file placement into game directories needed.
- Ephemeral TLS certificates — CA and per-host certificates are generated in memory at runtime. Nothing left on disk.
- Validated upstream connections — All traffic forwarded to real NMS servers uses proper SSL certificate validation
- HTTP keep-alive — Handles multiple requests per connection
- Cross-platform — Windows (.exe with automatic UAC elevation) and Linux (./run.sh handles everything)
- Simple menu interface — Install hosts entries, start the proxy, uninstall when done

## Getting Started

1. Download your expedition from https://cwmonkey.github.io/nms-expeditions/
2. Place SEASON_DATA_CACHE.JSON next to the executable (Windows) or in the project directory (Linux)
3. Run the tool, install, start the proxy, launch NMS

See the README.md for detailed instructions.

## 1.1.0 — Windows Support

This release adds full Windows support. The proxy now works on both Windows (native) and Linux (Proton/Steam Deck).

### What's New

- Windows support — The game now connects through the proxy on Windows, with full multiplayer and discovery services working.
- Automatic CA certificate management — On Windows, the proxy installs a temporary CA certificate into the Trusted Root store on startup and removes it on shutdown. No manual certificate setup required.
- CRL server for SChannel compatibility — Windows' native TLS stack (SChannel) requires certificate revocation checking. The proxy serves an empty CRL on port 18625 to satisfy this requirement.
- Self-test on startup — The proxy verifies DNS redirects, TLS handshake, and (on Windows) OS-level certificate validation before you launch the game. Problems are reported with actionable guidance.
- DNS cache flush on Windows — `ipconfig /flushdns` is run automatically after hosts file changes so the game picks up the redirects immediately.

### Changed

- Proxy rewritten from asyncio to threaded sockets — The original asyncio-based proxy had platform-specific issues with TLS handling on Windows (`start_tls()` transport wiring, ProactorEventLoop incompatibilities). The proxy now uses plain `socket` + `ssl` with a thread per connection, which works reliably on both platforms.
- Single multi-SAN certificate — Instead of generating per-hostname certificates with SNI context switching, the proxy now generates one certificate covering all NMS hostnames. Simpler and avoids SChannel compatibility issues with mid-handshake context changes.
- 30-second socket timeout — Client connections that stall are cleaned up after 30 seconds, preventing handler threads from pinning indefinitely.
- UTF-8 encoding explicit — Expedition JSON files are now opened with `encoding="utf-8"`, fixing potential parsing failures on Windows where the default encoding may not be UTF-8.

### Technical Notes

The root cause of the Windows connectivity issue was SChannel's certificate revocation check. SChannel requires the ability to verify that a server certificate has not been revoked (via CRL or OCSP). The proxy's ephemeral certificates had no revocation infrastructure, causing SChannel to fail with `CRYPT_E_NO_REVOCATION_CHECK` and abort the TLS handshake. The fix was to generate an empty CRL signed by the CA and serve it via HTTP, with a CRL Distribution Point extension in the server certificate.

_This does not affect Linux — Proton/Wine's SChannel implementation does not enforce revocation checks._
